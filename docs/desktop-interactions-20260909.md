# 独立日程组件与任务操作

桌面曾两次出现无法点击，Application 事件记录 Explorer 崩溃。不能确定唯一原因，旧组件已停止。本版删除全部 Shell 父子窗口挂接及自动重新挂接逻辑：主窗口、圆点均为无父窗口的普通顶层窗口，不置顶，可通过任务栏恢复。重复启动通过命名事件显示现有窗口，不创建重复实例。保留软件渲染。

日程任务旁的圆圈可完成或撤销完成，待安排列表也支持。点击后从服务器获取最新文档，用 revision 条件写入，仅修改对应 xzx 任务的 done，保留未知字段和其他成员任务。409 时重新基于服务器返回的最新文档提交，最多四次；任务被删除、改归属、ID 重复或数据损坏时停止写入。请求有 12 秒超时；保存期间禁用按钮；只在服务器确认后显示完成状态。读取轮询通过操作代数和文档 revision 丢弃过期响应。

保留单日、近三天、日期选择及 15 秒同步，滚轮和滚动条可浏览长列表。原“下一项”卡片不再显示。

验证结果：

- 生产构建及 30 个 Node 测试通过。
- 独立浏览器测试覆盖跨月三天、空日、视图记忆、完成/撤销/重新加载、备注及其他成员数据保留、409 并发更新、断网、401、重复点击禁用、延迟旧轮询及长列表滚轮操作。
- 原生验证通过无父窗口/非 WS_CHILD、无强制置顶、拖动、边缘缩放、Esc 取消、最小化恢复、HTTPS 同步、非黑屏截图、重新渲染、圆点收起展开与关闭。初次显示圆点会应用显示器 DPI，本版在 Show 后设置最终尺寸，修复缩放造成的尺寸偏差。
- 公网验证三天切换、刷新保留、三个日期分组、无下一项卡片、HTTPS 同步通过。没有更改用户实际任务的完成状态来做测试。
- 新程序已替换本机安装版本并打开；status.json 报告 independent、page-synced、parentClass 为空、topmost=false，Explorer 进程仍响应。
- 实际电脑截图看到正常蓝色圆点。用户在操作收起/展开，窗口句柄在观察与点击间变化，因此停止竞争性 UI 输入；未把截图或自动化通过当作长时间桌面稳定性的证明。

发布以服务器当时正在使用的 `20260909-repeat-edit-scope/source` 为基础，仅覆盖本次三个 desktop 页面文件，保留其他任务刚发布的重复日程编辑功能。先完成镜像构建，再切换并验证 HTTPS。生产镜像 `tongpin-team-workspace:20260909-desktop-interactions`，旧容器 `tongpin-before-desktop-interactions` 保留以便回退。邀请码和会话不进入源码、报告或命令参数。

限制：现在是独立窗口，不是壁纸层；Win+D 可最小化它，用桌面快捷方式、任务栏或托盘恢复。完成操作仅针对 xzx 个人日程的 done 状态，不涉及团队金额或任务产出计算。长期稳定性仍需实际使用反馈。
